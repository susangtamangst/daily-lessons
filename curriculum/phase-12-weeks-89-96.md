# Phase 12 — Weeks 89–96: Automation, Go Awareness, DSA, Coding, System Design

## Week 89 — Python automation project
Day 1: choose a real ops problem: cluster health/reporting, stale resources, or deployment checks. Day 2: design CLI inputs/outputs and failure behavior. Day 3: implement API/client layer with timeouts and structured errors. Day 4: add unit/integration tests and inject API failure. Day 5: package the tool and add CI. Day 6: code-review your own tool for readability, complexity, and security. Day 7: demo from clean environment and document usage.

## Week 90 — Go awareness for infrastructure roles
Day 1: syntax, types, functions, packages. Day 2: slices/maps and error handling. Day 3: build a tiny HTTP/CLI utility comparable to your Python tool. Day 4: goroutine/channel concepts with a small bounded-concurrency exercise. Day 5: compare Python vs Go for infra tooling. Day 6: interview drill reading simple Go code. Day 7: decide whether deeper Go study is needed for target roles; no forced language switch.

## Week 91 — DSA: arrays, strings, hash maps
Day 1: arrays/lists and two-pointer basics. Day 2: strings and frequency counting. Day 3: hash map/set lookup patterns. Day 4: solve 2 easy + 1 medium problems timed. Day 5: explain time/space complexity aloud. Day 6: mock coding interview emphasizing communication/tests. Day 7: redo missed problems without solutions and record patterns.

## Week 92 — DSA: stacks, queues, linked lists
Day 1: stack/LIFO and parentheses-style problem. Day 2: queue/BFS intuition. Day 3: linked-list traversal/reversal. Day 4: solve 3 targeted problems. Day 5: edge cases: empty, one element, cycles. Day 6: timed mock interview. Day 7: pattern review and handwritten complexity notes.

## Week 93 — DSA: trees, heaps, graphs
Day 1: binary tree DFS. Day 2: BFS/level order. Day 3: heap/top-K pattern. Day 4: graph traversal/visited set. Day 5: solve mixed infra-flavored scheduling/dependency problems. Day 6: mock interview. Day 7: redo weakest pattern from memory.

## Week 94 — Coding interview patterns
Day 1: clarify constraints/examples before coding. Day 2: brute force → optimize workflow. Day 3: test cases before submit. Day 4: 45-minute medium problem under interview rules. Day 5: review common bugs and Python idioms. Day 6: full mock with verbal reasoning. Day 7: create personal coding checklist and target weak patterns.

## Week 95 — System design: URL shortener
Day 1: requirements and scale assumptions. Day 2: API/data model and key generation. Day 3: cache/database/read-write path. Day 4: availability, replication, hotspots. Day 5: monitoring/security/abuse. Day 6: 45-minute whiteboard-style mock. Day 7: write final design with tradeoffs and failure modes.

## Week 96 — System design: metrics platform
Day 1: ingestion requirements and cardinality. Day 2: agents/scrape/push tradeoffs. Day 3: storage/index/retention. Day 4: query path and aggregation. Day 5: scale, sharding, reliability, cost. Day 6: mock design interview. Day 7: phase checkpoint: present metrics system and compare it to Prometheus experience from your lab.
